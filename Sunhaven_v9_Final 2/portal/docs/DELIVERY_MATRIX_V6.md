# Version 6 delivery matrix against the project proposal

A status of **Lab demonstrated** means a reproducible local function with fictional records and available tests. **Documented** means a written design or procedure. **External validation** requires an actual lab tenant, faculty feedback or an assessment submission artefact beyond this ZIP.

| Proposal deliverable | Current evidence | Status | Work needed for a complete assessed group submission |
|---|---|---|---|
| D1 Problem and scope baseline | Original proposal and `FINAL_PROJECT_OPERATING_GUIDE.md` | Documented | Confirm current marking scope and approved architecture with the lecturer |
| D2 Requirements and traceability | `REQUIREMENTS_CHECKLIST.md`, Policies & risks, this matrix | Lab demonstrated in part | Add final requirement IDs, acceptance signatures and individual contribution evidence |
| D3 Complete solution design | `ARCHITECTURE_V6.md`, source modules, trust boundaries | Documented | Review changed Flask/PowerShell design with assessor |
| D4 Security governance pack | `POLICY_SECURITY_PACK.md`, controls P01–P10, agency workflow | Documented | Obtain actual owner approval, retention schedule and staff training if real use |
| D5 Risk management pack | Seven security risks R01–R07 and treatments | Documented in part | Add separately scored project delivery register, owners and residual acceptance |
| D6 Identity platform implementation | Optional Entra OIDC code, synthetic users/roles | External validation | Actual test tenant, app registration, MFA, role mapping and screenshots |
| D7 JML automation engine | Local/mock JML and reviewed expiry automation | Lab demonstrated | Real Graph/PowerShell choice, partial failure recovery and identity readback in test tenant |
| D8 Secure care portal | Server role/assignment checks, notes, reviews, reports | Lab demonstrated | Original proposal says Flask; verify design-change approval and cross-browser acceptance |
| D9 Policy compliance engine | C01–C08 findings and role-protected views | Lab demonstrated | Compare against actual Entra and portal state, not local simulated fields |
| D10 Access review and audit evidence | Review decisions, tasks, ledger, correlation IDs | Lab demonstrated | Off-host durable log retention and actual integration evidence |
| D11 Test and evaluation pack | 47 tests, synthetic sample outputs, HTTP checks | Lab demonstrated in part | Target browser QA, live tenant failure tests, measured metrics and signed evidence index |
| D12 Solution handover | README, operating DOCX, security pack and runbook | Documented | Record assessment video, authentic screenshots and final report |

The independent solo prototype can demonstrate the whole **local** workflow. No document or visual may convert a local simulated state into a claim of live Microsoft identity or industry certification.
